# DeerGPT — архитектура, версия 2.0

**Дата:** 10 сентября 2026
**Сервис:** https://deergpt.ru
**Репозиторий:** https://github.com/dsanatov-rgb/deergpt (последний коммит `3501170`)
**Заменяет:** версию 1.x — сборку на VK Cloud с локальным Whisper и фронтендом на хостинге reg.ru

---

## 1. Назначение

DeerGPT — голосовой экскурсовод по **скифскому звериному стилю**. Пользователь задаёт вопрос голосом и получает короткий устный ответ (одно-два предложения) в манере экскурсовода. Ответы строятся строго по коллекции научных текстов; выдумывать модели запрещено.

Два режима ответа:

- **Обычный вопрос** («Что такое звериный стиль?») — RAG-ответ по коллекции текстов.
- **«Интересный факт»** («Расскажи что-нибудь интересное», «Удиви меня», «Что интересного про грифонов?») — готовый проверенный факт из отобранной базы, озвученный более азартной манерой.

Доступ закрыт жетонами: без валидной куки API не отвечает.

## 3. Общая схема

```
Браузер (MediaRecorder, запись голоса)
   │  HTTPS, кука deergpt_auth
   ▼
Nginx — deergpt.ru, TLS Let's Encrypt
   ├── /            → статика /var/www/deergpt
   └── /api/        → http://127.0.0.1:8000/  (префикс срезается)
   ▼
FastAPI (main.py, uvicorn, systemd deergpt.service)
   ├── POST /auth   → tokens.txt → HMAC-кука на 30 дней
   └── POST /voice
         1. Распознавание ─────────────► proxyapi: whisper-1
         2. is_fact_request(текст)?
              нет → answer_with_rag ──► Qdrant pdf_chunks + proxyapi: эмбеддинги, gpt-5.4-nano
              да  → answer_fact ──────► Qdrant facts (+ эмбеддинг темы при необходимости)
         3. _sanitize_tts — очистка текста под озвучку
         4. _synthesize ───────────────► proxyapi: gpt-4o-mini-tts, echo
                                          └ сбой или таймаут 15 с → gTTS
         5. mp3 → браузер

Qdrant (Docker, 127.0.0.1:6333)
   ├── pdf_chunks — 1624 фрагмента научных текстов и Геродота
   └── facts      — 21 отобранный факт
```

Все внешние модели вызываются через **proxyapi.ru** одним ключом и одним балансом.

## 5. Компоненты

### 5.1. Nginx
Один server-блок (`deploy/nginx-deergpt.conf`): статика из `/var/www/deergpt`, `location /api/` с `proxy_pass http://127.0.0.1:8000/` (слэш в конце обязателен), `client_max_body_size 25M`, таймауты чтения и отправки 120 с, редирект HTTP → HTTPS. CORS не нужен: фронтенд и API на одном origin, адреса во фронтенде относительные.

### 5.2. Бэкенд — `main.py`
FastAPI под uvicorn на `127.0.0.1:8000`, юнит `deploy/deergpt.service` с `Restart=always`.

| Эндпоинт | Назначение |
|---|---|
| `GET /` | проверка живости, `{"status": "ok"}` |
| `POST /auth` | проверка жетона, установка куки |
| `POST /voice` | полный цикл: аудио → текст → ответ → mp3 |
| `GET /tts/{uid}.mp3` | повторная выдача сгенерированного файла |

Ключевые функции: `_transcribe` (STT), `_sanitize_tts` (очистка текста), `_synthesize` (TTS с запасным вариантом), `_valid_cookie` (авторизация).

### 5.3. RAG и факты — `rag.py`
Клиенты Qdrant, эмбеддингов (`OpenAIEmbeddings`) и чат-модели (`ChatOpenAI`, `max_tokens=140`, `temperature=0.2`). Функции: `get_contexts`, `answer_with_rag`, `is_fact_request`, `_fact_topic`, `answer_fact`, `_answer_fact_llm` (запасной режим).

### 5.4. Qdrant
Контейнер `qdrant/qdrant:v1.15.4`, `--restart always`, порт только на `127.0.0.1:6333`, данные в `/home/user1/rag2_project/qdrant_data`. Отдельного systemd-юнита нет — автозапуск обеспечивает Docker.

### 5.5. Внешние модели (proxyapi.ru)

| Задача | Модель | Где используется |
|---|---|---|
| Распознавание речи | `whisper-1` | каждый запрос `/voice` |
| Ответ по контексту | `gpt-5.4-nano` | обычный режим; запасной режим факта |
| Эмбеддинги | `text-embedding-3-small` (1536) | поиск по коллекциям |
| Синтез речи | `gpt-4o-mini-tts`, голос `echo` | каждый запрос `/voice` |
| Извлечение и проверка фактов | `gpt-5.4-mini` | только офлайн-конвейеры, не в сервисе |

### 5.6. Фронтенд
Одна страница `index.html` с изображениями и фавиконами. Запись голоса через `MediaRecorder`, запросы на относительные `/api/auth` и `/api/voice`, кнопка воспроизведения переключается по событиям аудиоэлемента. **Единственный источник фронтенда — папка `frontend/` репозитория**; на сайт выкладывается копированием в `/var/www/deergpt`.

## 6. Поток запроса `/voice`

1. Браузер отправляет запись; без валидной куки — `401`.
2. Аудио сохраняется во `/tmp/in_{uid}_…`, распознаётся `whisper-1` (~0,8 с).
3. `is_fact_request` решает, какой режим включить (микросекунды, без вызова модели).
4. Ответ:
   - обычный режим — поиск трёх фрагментов в `pdf_chunks` и генерация (~1,5 с);
   - режим факта — выбор из базы `facts` (0–0,3 с).
5. `_sanitize_tts` убирает разметку, ссылки, инициалы, разворачивает сокращения и римские века, обрезает по границе предложения.
6. `_synthesize` озвучивает текст голосом echo (~3–3,5 с на 180–250 символов) в `/tmp/tts_{uid}.mp3`.
7. Файл возвращается браузеру.

**Полный цикл на сервере:** ~5–6 с в обычном режиме, ~4,5 с в режиме факта.

## 7. Режимы ответа

### 7.1. Обычный RAG
`answer_with_rag`: три ближайших фрагмента из `pdf_chunks`, промпт требует отвечать строго по контексту и писать под озвучку — без разметки, ссылок, фамилий и сокращений, числа и века словами, одно-два предложения, манера экскурсовода.

### 7.2. «Интересный факт»

**Распознавание запроса** (`is_fact_request`) без вызова модели:
- сильные признаки — «факт» (но не «фактически»), «удиви», «что интересного / любопытного / необычного»;
- слабые признаки — «интересн / любопытн / удивительн / необычн» только вместе с просьбой («расскажи», «что-нибудь», «давай», «ещё»).

Так вопросы вида «Интересно, кто такие скифы?» уходят в обычный режим.

**Выделение темы** (`_fact_topic`): из фразы убираются слова-просьбы, признаки факта и слова на «скиф». Остаток — тема («грифонов», «петра первого»).

**Выбор факта** (`answer_fact`):
1. Нет темы → случайный факт.
2. Есть тема → **поиск по словам**: основы слов темы (отсечение двух последних букв, ё = е) ищутся в тексте фактов.
3. По словам не нашлось → **векторный поиск** по `facts` с порогом `FACT_MIN_SCORE = 0.3`.
4. Не нашлось и так → фраза «Про это у меня пока ничего нет, зато вот другое!» и случайный факт.

Последние 5 выданных фактов не повторяются. Перед фактом ставится один из шести зачинов («А вот удивительный факт!», «Готовы удивиться?» и др.), два одинаковых подряд не бывает.

**Запасной режим.** Если коллекция `facts` недоступна или пуста, работает `_answer_fact_llm`: модель выбирает факт из случайных фрагментов `pdf_chunks`. Качество заметно ниже — это только страховка.

## 8. Озвучка

`_synthesize(text, path, instructions)` — клиент на базе `stt_client` с таймаутом 15 с и без повторов, потоковая запись mp3.

| Манера | Переменная | Когда |
|---|---|---|
| Живой экскурсовод: тепло, улыбка в голосе, чуть бодрее обычного | `TTS_INSTRUCTIONS` | обычные ответы |
| Азартный рассказчик: заговорщицкое начало, нарастающее удивление | `TTS_FACT_INSTRUCTIONS` | режим факта |

При ошибке или таймауте — gTTS (другой голос, но сервис не замолкает). В журнал пишутся строки `TTS echo: 3.16 s, 194 chars` и `TTS echo [fact]: …`; сбой — `TTS failed … fallback to gTTS`.

Голос выбран сравнением на тестовых фразах: coral, nova, ash, verse, затем ash, ballad, echo, onyx, cedar; выбран **echo**.

## 9. Авторизация

1. `tokens.txt` — 25 жетонов, по одному в строке (chmod 600, вне git).
2. `POST /api/auth` с жетоном → при совпадении HttpOnly-кука `deergpt_auth` на 30 дней; значение — HMAC жетона секретом `AUTH_SECRET`, сам жетон в куке не хранится.
3. `/voice` без валидной куки → `401`.
4. Каждый вход пишется в `access_tokens.log`.

Жетоны добавляются и отзываются правкой `tokens.txt` без перезапуска: файл читается на каждом запросе.

## 10. Данные

### 10.1. Коллекция `pdf_chunks`
1624 точки, векторы 1536. Схема payload: `fname`, `file`, `chunk_idx`, `path`, `text`.

Основу составляют искусствоведческие тексты: каталог вещей (`artofanimstyle`, 604 фрагмента), язык звериного стиля (`animstylelanguage`, 261), статьи о грифонах и изображениях (`47-425-2-PB`, 163), Сибирская коллекция Петра I (`sibirskayakollpetra1`, 157) и ещё 15 текстов меньшего объёма. В версии 2.0 добавлен Геродот (`herodotus4`, 80).

### 10.2. Геродот, книга четвёртая
- **Источник:** перевод Ф. Г. Мищенко (1888) на Викитеке — общественное достояние. Перевод Стратановского (1972) не используется: он под авторским правом.
- **Отбор глав под звериный стиль:** 5–15 (легенды о происхождении, золотые дары с неба, змееногая дева), 23–31 (аримаспы и грифы, исседоны), 59–82 (боги, жертвоприношения, погребения, обычаи), 103–117 (соседи скифов: тавры, агафирсы, невры, будины, савроматы). Войны, география, Ливия не взяты.
- **Исправления текста:** три ошибки нумерации глав на Викитеке (48 → 42, 51 → 57, 133 → 113).
- **Нарезка:** фрагменты до ~700 знаков; соседние главы склеиваются, через пропуск — нет.
- **Строка «Кратко»:** перед каждым фрагментом современный пересказ (`gpt-5.4-mini`) с принятыми сегодня названиями — «змееногая дева», «грифоны». Нужна только для поиска: сам текст не меняется, при извлечении фактов строка отбрасывается.
- **Скрипт:** `herodotus_load.py`, идемпотентный — удаляет прежние фрагменты `herodotus4` и записывает заново.

### 10.3. Коллекция `facts`
21 факт, собирается из `facts_curated.jsonl` скриптом `facts_load.py` (коллекция пересоздаётся целиком). Состав:
- звериный стиль (4): три мира зверей, тигр и верблюд, бляха с грифонами, войлочный ковёр;
- как сибирское золото попало в музей (4): указ Петра, Кунсткамера 1726, пираты 1704, дар Демидова;
- мифы за образами, по Геродоту (7): золотые дары с неба, змееногая дева, чаши на поясах, грифы и аримаспы, позолоченные черепа исседонов, невры-волки, мраморные грифоны у дома Скила;
- золото и кони в обычаях, по Геродоту (6): чаши из черепов, царские погребения, стража всадников, агафирсы, савроматки, баня с коноплёй.

**Принципы отбора** (действуют и для будущих пополнений):
- связь с образами звериного стиля: звери и фантастические существа, золото, мифы и обычаи за образами;
- легенда и рассказ древнего автора подаются как легенда и рассказ («Геродот пишет…», «по скифской легенде…»);
- понятно неспециалисту: без фамилий, названий музеев и курганов, терминов без пояснения;
- жестокие факты без связи со стилем не берутся;
- каждый факт сверен с источником; формулировки, написанные вручную, сверены с текстом Геродота.

### 10.4. Конвейер извлечения фактов
`facts_build.py` — офлайн, `gpt-5.4-mini`, батчи по 5 фрагментов, 4 потока, докачка при сбое.

1. **Извлечение:** только факты с оценкой 3+ по общей шкале удивительности с ориентирами уровней.
2. **Проверка:** второй вызов сверяет каждый факт с фрагментом (числа, народ, домыслы, легенда как легенда, понятность) и заново ставит оценку.
3. **Результат:** `facts_raw.jsonl` (основная коллекция) и `facts_raw_{FILE}.jsonl` при запуске с `FACT_FILE=<file>`.
4. **Ручной отбор** → `facts_curated.jsonl` → `facts_load.py`.

**Выход по прогонам:** основная коллекция (1544 фрагмента, ~650 тыс. токенов) — 169 проверенных фактов, из них с оценкой 3+ только 24; Геродот (80 фрагментов, ~56 тыс. токенов) — 48 проверенных. Вывод: искусствоведческие тексты дают мало фактов для слушателя, мифы и история находок — основной источник.

## 14. Ограничения и технический долг

**Качество ответов**
- Эпизоды Геродота про змееногую деву и золотые дары с неба не всегда попадают в тройку источников обычного RAG: их вытесняют научные статьи на близкие темы. Направления: больше источников в контексте, гибридный поиск по словам и векторам.
- Порог `FACT_MIN_SCORE = 0.3` пограничный; при росте базы фактов нужна перекалибровка.
- Поиск темы по основам слов грубый («кон» от «коней» совпадает и с «коноплёй»); при росте базы — заменить на лемматизацию.
- В базе фактов нет ни одного факта про оленя, хотя олень — символ сервиса; в списке стоп-слов темы есть «олень», поэтому запрос «интересное про олень» даёт случайный факт.
- База фактов маленькая (21), при частом использовании факты будут повторяться.

**Эксплуатация**
- Нет ротации журнала systemd и `access_tokens.log` при диске 20 ГБ.
- Проверить, очищаются ли временные файлы `/tmp/in_*` и `/tmp/tts_*`.
- Единственная ВМ без резервирования; при недоступности proxyapi.ru не работает распознавание и обычные ответы (озвучка переходит на gTTS).
- В корне репозитория лежат скрипты 1.x (`whisper_asr.py`, `tts.py`, `tts_test.py`, `pdf_parser.py` и др.) — разобрать, что устарело.

**Безопасность и оплата**
- Включить автоплатёж в cloud.ru (на балансе и харнесс МИФИ).
- Проверить и освободить публичный IP `46.16.36.222` от первой неудачной ВМ.
- Отозвать старые токены GitHub (учесть, что у харнесса МИФИ токен зашит в адрес remote); сверить, что в `.env` новый ключ proxyapi.ru.
- Проверить удаление проекта VK Cloud `rag_skifgold` и прекращение списаний.
